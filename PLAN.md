## Architecture

### Component Diagram

```
┌─────────────────────────────────────────────────────────────────────┐
│  TELEGRAM                                                         │
│  - Bot: single conversation per agent                              │
│  - NO typing indicator during tool execution                      │

└──────────────────────────┬────────────────────────────────────────┘
                           │

┌─────────────────────────────────────────────────────────────────────┐
│  LLM PROVIDER ABSTRACTION                                         │
```

### Input Queue Model

```
User sends message during tool execution
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  INPUT QUEUE                                                 │
│  - Accumulate: all user inputs during tool execution         │
│  - Ordering: tool_result at FRONT, user inputs after         │
│    (tool_call → tool_result sequence preserved)              │
│  - On tool result: inject result + all queued inputs         │
│  - Next LLM call = combined input                            │
└─────────────────────────────────────────────────────────────┘
```

**Concurrency:** If multiple messages arrive during tool execution, all accumulate. Next LLM call receives: tool_result + [all accumulated user inputs].

### Config Discovery (assignment confirmed)

```
/agents/                           → org-level configs
/agents/{company}/                 → company-level (empty allowed)
/agents/{company}/{agent}/          → agent-level (empty allowed)
```

Each config file (`agent.json`, `role.md`, `telegram.json`) completely overrides the parent level. No merging. Scanner stops at first hit.

**Scan root boundary:** Scanner stops at the first `/agents/` ancestor it finds. If CWD is `/agents/company/agent/`, it scans: `/agents/company/agent/` → `/agents/company/` → `/agents/` → STOP. Never walks above `/agents/`.

Config files per level:
- `agent.json` — LLM provider, API key, model
- `role.md` — agent instructions (system prompt content)
- `telegram.json` — Telegram bot config (optional, incomplete = flagged)
- `memory/` — agent-managed memory files
- `skills/` — Anthropic-compatible skill registry

### LLM Provider Abstraction

```csharp
// Provider = API format standard (OpenAI-compatible, Anthropic, etc.)
// base_url = actual endpoint
// model = which model at that endpoint
// api_key = auth token

public record LlmConfig(
    string Provider,      // "openai" (format standard)
    string BaseUrl,      // "https://api.minimax.chat/v1"
    string ApiKey,       // auth
    string Model         // "MiniMax-Text-01"
);
```

### Tool Execution Model

```
LLM outputs: "I'm reading the config..." + tool_call {read_file}
    │
    ▼
Bridge sends text to Telegram immediately
Agent Runtime pauses LLM call
Bridge executes tool via callback
Tool result + accumulated user inputs → injected into next LLM call
LLM continues → final response
```

**MiniMax interleaved tools:** LLM outputs text and tool calls mixed. Text goes to Telegram immediately (filtered for internal tokens). Tool execution happens async, then combined with queued user input for the next LLM call.

### Interfaces (multi-agent ready from day one)

```csharp
// ITelegramBridge - handles Telegram connection
public interface ITelegramBridge {
    Task SendMessageAsync(string text, CancellationToken ct);
    void OnMessage(Func<Message, Task> handler);
}

// IAgentRuntime - orchestrates LLM + tools
public interface IAgentRuntime {
    Task<string> ProcessAsync(string userInput, AgentConfig config, CancellationToken ct);
    void EnqueueUserInput(string input);  // input queue
}

// IToolExecutor - runs tools
public interface IToolExecutor {
    Task<ToolResult> ExecuteAsync(ToolCall call, string agentContextFolder, CancellationToken ct);
}

// ILlmProvider - LLM abstraction
public interface ILlmProvider {
    IAsyncEnumerable<string> StreamAsync(LlmInput input, CancellationToken ct);
    Task<string> CompleteAsync(LlmInput input, CancellationToken ct);
}
```

- Provider projects: named after API format standard (`OpenAi`), not hosting provider

## Failure Modes

| Component | Failure | User impact | Protected? |
|-----------|---------|-------------|------------|
| LLM timeout | No response | User sees timeout message | Need explicit timeout + retry |
| Telegram token invalid | Can't connect | Nothing works | Config validation at startup |
| Skills folder missing | No tools available | Agent can only chat | Static skills required, fail fast if missing |
| Config file incomplete | e.g., telegram.json no API key | Agent flagged at startup | Incomplete flag, not silent ignore |
| Tool execution error | Tool throws | Error fed to LLM, LLM explains | Need error wrapping in ToolResult |
| Memory file write fail | Agent can't persist | LLM forgets between calls | Need error handling |
| Input queue overflow | Many rapid messages | Oldest dropped? Or bounded queue | Need max queue size |
