## Architecture

### Component Diagram

```
TELEGRAM
  └─ Bot: long-poll, single conversation per agent
      └─ TelegramBridge: SendMessageAsync + OnMessage handler

BRIDGE → AGENT RUNTIME → LLM PROVIDER
              ↓
         TOOL EXECUTOR
              ↓
         TOOL BASE (registered)
```

### Config Discovery

```
/agents/                           → org-level configs (depth 1)
/agents/{company}/                 → company-level (depth 2)
/agents/{company}/{agent}/         → agent-level (depth 3+)
```

Scanner walks UP from startPath, stops at first `/agents/` ancestor. First-hit-wins per filename. Each level can have: `agent.json`, `role.md`, `telegram.json`.

### Tool vs Skill (orthogonal layers)

**Tool** = .NET class with typed input/output. `ToolBase` provides reflection-based schema. ToolExecutor knows nothing about skills.

**Skill** = LLM-facing metadata (name, description, usage hints). Loaded from `skills/*.md`. Maps to capabilities, not necessarily to tools. ISkillRegistry holds skill metadata.

```
LLM ← skill descriptions (ISkillRegistry)
LLM → tool_calls → ToolExecutor → ToolBase → result
```

### Input Queue Model

```
User message during tool execution
    ↓
LockedQueue<string> accumulates all inputs
    ↓
On tool result: inject result + ALL queued inputs into next LLM call
```

## Interface Summary

```csharp
// LLM abstraction
interface ILlmProvider {
    IAsyncEnumerable<string> StreamAsync(LlmInput input, CancellationToken ct);
    Task<string> CompleteAsync(LlmInput input, CancellationToken ct);
}

// Telegram bot
interface ITelegramBridge {
    Task SendMessageAsync(string text, CancellationToken ct);
    void OnMessage(Func<string, Task> handler);
}

// Tool execution (knows nothing about skills)
interface IToolExecutor {
    Task<ToolResult> ExecuteAsync(ToolCall call, CancellationToken ct);
    void RegisterTool(string name, ToolBase tool);
}
abstract class ToolBase {
    public abstract string Name { get; }
    public abstract Task<object> ExecuteAsync(object input, CancellationToken ct);
    public ToolSchema GetSchema();
}

// Skills (LLM-facing, independent of tools)
interface ISkillRegistry {
    IReadOnlyList<SkillEntry> GetAllSkills();
    SkillEntry? GetSkill(string name);
}
record SkillEntry(string Name, string Description, IReadOnlyList<ToolSchema>? Tools, string Markdown);

// Agent orchestration
interface IAgentRuntime {
    Task<string> ProcessAsync(string userInput, CancellationToken ct);
    void EnqueueUserInput(string input);
}
```

## Failure Modes

| Component | Failure | User impact |
|-----------|---------|-------------|
| LLM timeout | No response | User sees timeout message |
| Telegram token invalid | Can't connect | Nothing works |
| Tool not registered | Error fed to LLM | LLM explains the gap |
| Memory file write fail | Agent can't persist | LLM forgets between calls |
